    Модуль 3. Проектирование, разработка и оптимизация веб-приложений

    Внимание! Данный раздел является дополнительным и скорее всего не будет использован на экзамене.

    1. Теория

    Общие требования

    Доработайте базу данных таким образом, чтобы она обеспечивала решение всех задач, поставленных заказчиком в предыдущих модулях.

    Для повышения удобства разработки допускается использование фреймворков и библиотек, позволяющих реализовать:

    • дружественный пользовательский интерфейс;
    • технологичность и масштабируемость приложения.

    В процессе разработки необходимо:

    • интегрировать адаптивный дизайн;
    • обеспечить высокое качество программного кода;
    • предусмотреть анимацию и микроанимации для улучшения пользовательского опыта.

    Требования к сдаче практической работы

    Все результаты передаются через индивидуальный репозиторий системы контроля версий.

    Необходимо выполнить коммиты:

    • в начале выполнения работы;
    • по завершении выполнения модуля.

    Необходимые приложения

    • Прил_ОЗ_КОД 09.02.07-3-2026-М3.zip

    2. Задание

    1. Доработка базы данных под задачи заказчика

    1.1. Исправить слабые места текущей схемы

    В текущей БД есть проблемы:

    1. users.login допускает NULL
    2. users.email не уникален
    3. reviews.created_at — int и содержит 0

    1.2. Создать файл миграции

    Создать файл:

    id="mig1path"
db/migrations/001_fix_schema.sql

    Вставить:

    USE korochki;

-- 1) login сделать обязательным
ALTER TABLE users
  MODIFY login VARCHAR(50) NOT NULL;

-- 2) email сделать уникальным
ALTER TABLE users
  ADD UNIQUE KEY uq_users_email (email);

-- 3) reviews.created_at сделать timestamp с автозаполнением
ALTER TABLE reviews
  MODIFY created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP;

-- 4) reviews.text расширить (200 символов часто мало)
ALTER TABLE reviews
  MODIFY text TEXT NOT NULL;

-- 5) payment_methods.name сделать уникальным (как справочник)
ALTER TABLE payment_methods
  ADD UNIQUE KEY uq_payment_methods_name (name);

    1.3. Проверка результата

    В phpMyAdmin → вкладка Structure:

    • users.login = NOT NULL
    • users.email имеет UNIQUE
    • reviews.created_at = TIMESTAMP DEFAULT CURRENT_TIMESTAMP

    1.4. Закрепить «курсы только из списка» на уровне БД

    Сейчас applications.course_name — свободный текст. Это позволяет указывать любые курсы, что противоречит требованиям (там 3 фиксированных курса).

    1.4.1. Создать справочник курсов

    Создать файл:

    db/migrations/002_courses_dictionary.sql

    Вставить:

    USE korochki;

-- 1) создать справочник курсов
CREATE TABLE IF NOT EXISTS courses (
  id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(200) NOT NULL UNIQUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 2) заполнить 3 курса из задания
INSERT IGNORE INTO courses (name) VALUES
('Основы алгоритмизации и программирования'),
('Основы веб-дизайна'),
('Основы проектирования баз данных');

-- 3) добавить course_id в applications
ALTER TABLE applications
  ADD COLUMN course_id INT NULL AFTER user_id;

-- 4) проставить course_id по старому course_name
UPDATE applications a
JOIN courses c ON c.name = a.course_name
SET a.course_id = c.id;

-- 5) сделать course_id обязательным и добавить FK
ALTER TABLE applications
  MODIFY course_id INT NOT NULL,
  ADD CONSTRAINT fk_applications_course
    FOREIGN KEY (course_id) REFERENCES courses(id)
    ON UPDATE CASCADE;

-- 6) убрать старое поле (после успешного обновления)
ALTER TABLE applications
  DROP COLUMN course_name;

    1.4.2. Проверка результата

    • Таблица courses создана и содержит 3 записи
    • В applications есть course_id
    • Поле course_name удалено
    • Включён FK applications.course_id → courses.id

    2.2. Обновить backend под courses

    2.2.1. Обновить SELECT в /api/applications/my

    Теперь курс берётся через JOIN courses:

    SELECT
  a.id,
  c.name AS course_name,
  DATE_FORMAT(a.start_date, '%Y-%m-%d') AS start_date,
  pm.name AS payment_method,
  st.name AS status,
  DATE_FORMAT(a.created_at, '%Y-%m-%d %H:%i:%s') AS created_at
FROM applications a
JOIN courses c ON c.id = a.course_id
JOIN payment_methods pm ON pm.id = a.payment_method_id
JOIN application_statuses st ON st.id = a.status_id
WHERE a.user_id = %s;
    2.2.2. Изменить INSERT при создании заявки

    Перед вставкой заявки получить course_id:

    SELECT id FROM courses WHERE name=%s;

    Вставлять course_id вместо course_name:

    INSERT INTO applications (user_id, course_id, start_date, payment_method_id, status_id)
VALUES (%s, %s, %s, %s, %s);

    3. Адаптивный дизайн

    Чтобы на всех страницах не было «разъезда», придерживаться единой структуры:

    • <body class="container">
    • заголовок h1
    • основной блок в .card
    • формы: .field + label + input/select/textarea
    • кнопки в .actions
    • сообщения — #msg

    4. Высокое качество кода

    На каждой странице добавить блок сообщений:

    <div id="msg" class="msg"></div>

    Функция сообщений (одинаковая для всех страниц):

    function setMsg(text, type="") {
  const el = document.getElementById("msg");
  if (!el) return;
  el.className = type ? `msg ${type}` : "msg";
  el.textContent = text || "";
}

    5. Анимации и микроанимации

    Добавить в styles.css:

    /* microanimations */
button, a, input, select, textarea {
  transition: transform 120ms ease, filter 120ms ease, box-shadow 120ms ease, border-color 120ms ease;
}

button:active {
  transform: scale(0.98);
}

.card {
  transition: transform 160ms ease, box-shadow 160ms ease;
}

.card:hover {
  box-shadow: 0 10px 26px rgba(0,0,0,0.08);
}

input:focus, select:focus, textarea:focus {
  box-shadow: 0 0 0 4px rgba(26,115,232,0.12);
}

    Баллы Критерии
    10 Реализованы миграции, введён справочник курсов, обновлён backend под courses, соблюдены требования API (нет дублей, нет хардкода 127.0.0.1), единые сообщения #msg, добавлены микроанимации, выполнены 2 коммита (старт/финал).
    8–9 Есть мелкие недочёты в SQL/миграциях или частично не обновлён backend (например один маршрут ещё использует course_name).
    5–7 Миграции выполнены частично или справочник courses создан, но проект не переведён на course_id в API/форме.
    1–4 Исправлена только малая часть схемы (например только users.login/email), без курсов и без обновления backend.
    0 Работа выполнена полностью или частично с использованием систем искусственного интеллекта либо не соответствует требованиям/не содержит обязательных файлов/коммитов.
